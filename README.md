# Cardputer 三 app 固件

给 [M5Stack Cardputer-Adv](https://docs.m5stack.com/en/core/Cardputer-Adv) 写的两个小 app，共存于一个固件里，开机在菜单页选：

```
STACKM5

  1  JIANPU PLAYER
  2  VOCAB
  3  TV REMOTE

press 1-3
```

| app | 做什么 |
|---|---|
| **简谱演奏器** | 在 56 键键盘上敲入简谱，回车演奏。谱子存 Flash 曲库，断电不丢 |
| **背单词** | 翻卡片：先看单词，按键翻开英文释义和例句，再按键换下一个 |
| **电视遥控器** | 以 BLE HID 配对成蓝牙遥控器：方向键、音量、电源 |

一个固件装三个 app 的理由：Cardputer 一次只能跑一个固件，做成三个镜像就得来回烧写；而它们共享 LittleFS、键盘、离屏画布和文本折行，合在一起占 3.3MB app 槽的 38%。

## 硬件

Cardputer-Adv（ESP32-S3FN8 / 8MB Flash）。音频走 ES8311 编解码 + NS4150B 功放 + 1W 喇叭。
非 Adv 的老款 Cardputer 理论上也能跑（`M5Cardputer` 库同时支持两者），但没测过。

## 编译烧写

只需要 [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/index.html)，不需要 VS Code：

```bash
brew install platformio          # 或 uv tool install platformio

make            # 列出所有指令
make test       # 在电脑上跑单元测试（不需要设备，约 3 秒）
make flash      # 编译 + 烧写
make monitor    # 看串口输出
```

日常循环是 `make test && make flash`。

工具链、ESP32 平台包和依赖库都由 `platformio.ini` 自动下载，首次约 330MB。

开发板要选 `esp32-s3-devkitc-1`（不是 `m5stack-*` 系列）—— 这是官方文档指定的。

设备侧必须 `build_unflags = -std=gnu++11`：espressif32 平台会在我们的 flag
之后再追加它自己的 `-std`，而 gcc 取最后一个，所以只写 `build_flags` 是无效的。
不 unflag 的话设备侧是 C++11，会出现「Mac 上测过的代码在板子上编不过」。

# 简谱演奏器

```
01                    1=C 4/4 120
3 3 3- 3 3 3- 3 5 1 2 3---
4 4 4 4 4 3 3 3 3 2 2 3 2-5-▌
11 notes 16 beats 8.0s
ENTER play  =setup  `back
```

为什么用简谱而不是五线谱：简谱是**首调**记谱法，`1` 唱 do 但具体是哪个音由开头的 `1=C` 决定。想换调只改这一处，整首歌跟着搬，旋律不变 —— 谱子其他地方一个字都不用动。

## 简谱语法

### 头部行（第一行，可省略）

```
1=C 4/4 120
```

| 字段 | 含义 | 缺省 |
|---|---|---|
| `1=C` | 调号，决定 `1` 是哪个音。接受 `C C# D Eb E F F# G Ab A Bb B` | `1=C` |
| `4/4` | 拍号。**解析但忽略** —— 不画小节线，对发声无影响。保留只为抄谱时不报错 | `4/4` |
| `120` | 速度 BPM，真正决定快慢 | `120` |

### 音符

形式：`[#|b]` + `数字` + `[八度点…]` + `[时长修饰…]`

| 记号 | 含义 |
|---|---|
| `1`–`7` | 音级（do re mi fa sol la si） |
| `0` | 休止符 |
| `'` `,` | 高八度 / 低八度，可叠加（`1''` = 高两个八度） |
| `-` | 增时线，延长前一个音符一拍 |
| `/` | 减时线，时长减半，可叠加（`1//` = 1/4 拍） |
| `.` | 附点，时长 ×1.5 |
| `#` `b` | 升 / 降半音，写在数字**前面** |
| `\|` | 小节线，忽略（纯排版用） |

时长公式：`1 / 2^(斜杠数) × (有附点 ? 1.5 : 1) + 增时线个数`

| 输入 | 拍数 | |
|---|---|---|
| `1` | 1 | 中音 do |
| `1 -` / `1 - - -` | 2 / 4 | |
| `1.` | 1.5 | 附点 |
| `1/` / `1//` | 0.5 / 0.25 | 八分 / 十六分 |
| `1/.` | 0.75 | 附点八分 |
| `#1'/.` | 0.75 | 升高音do，附点八分（修饰符可叠） |

谱面解析失败时会精确报出错字符的下标，编辑器把它标红、拒绝播放 —— 不做「跳过错误继续播」，那样永远不知道哪里写错了。

## 按键

Cardputer 没有独立方向键。社区惯例的 `;`↑ `.`↓ `,`← `/`→ 与本语法的 `,`（低音点）`.`（附点）`/`（减时线）直接冲突，所以两个页面用不同的导航键 —— 编辑页只需要左右移光标，就用 `[` `]`（免 Shift、物理左右相邻、与语法零冲突）。

### 曲库页

| 键 | 作用 |
|---|---|
| `;` `.` | 上一首 / 下一首 |
| `⏎` | 打开编辑页 |
| `空格` | 直接播放，进全屏可视化页（不进编辑页） |
| `n` | 新建一首 |
| `⌫` | 删除（按两次确认） |
| `` ` `` | 回菜单页 |

### 可视化页

曲库页按 `空格` 播放成功就自动进入。读盘 / 解析失败、空谱、零时长时留在曲库页。

| 键 | 作用 |
|---|---|
| `空格` | 暂停 / 恢复 |
| `.` | 循环切换四种风格（频谱柱 / 音高卷帘 / 示波器 / 大字简谱） |
| `,` | 循环切换四种配色（灰 / 青 / 橙黄 / 绿） |
| `` ` `` | 停止并回曲库页 |

风格和配色只记在 RAM 里：本次开机内沿用，重启回到默认。曲子自然放完会自动回曲库页。

四种风格全部由**谱面数据**驱动，不采音频、不做 FFT —— 播放器是我们自己合成的音，
每个音的频率、起止时间、时值和 BPM 拍点都能确定性地算出来，比伪 FFT 更准也更便宜。

### 编辑页

| 键 | 作用 |
|---|---|
| `1`-`7` `0` | 音级 / 休止符，**按下即试听** |
| `'` `,` `-` `/` `.` `#` `b` | 修饰符（`#` 是 Shift+3） |
| `空格` | 分隔音符 |
| `[` `]` | 光标左移 / 右移 |
| `fn` + `[` `]` | 跳行首 / 行尾 |
| `⌫` | 退格 |
| `⏎` | 播放；播放中再按停止 |
| `=` | 调号 / 速度设置 |
| `` ` `` | 存盘并返回曲库页 |

即时试听是**回看光标左边那个音符**，不是「按哪个数字响哪个音」。因为修饰符是后敲的：输入高音 do 的按键顺序是 `1` 然后 `'`，按下 `1` 的瞬间程序还不知道后面要跟 `'`。回看的做法让你先听到中音、敲完 `'` 再听到高音 —— 听到的是修正过程。

### 设置页

| 键 | 作用 |
|---|---|
| `[` `]` | 切换调号，**每切一下用新调号响一声 do** |
| `;` `.` | 速度 ±5 |
| `⏎` `` ` `` | 返回编辑页 |

## 加内置曲子

往 `lib/songs/songs.cpp` 的数组里加一条，填上期望的音符数和总拍数：

```cpp
{
    "song-name",              // 中文名写注释里，标题用 ASCII（测试输出可读）
    "1=C 4/4 120",
    "3 3 4 5 5 4 3 2",
    8,                        // 期望音符数
    8.0f,                     // 期望总拍数
},
```

然后把 `src/main.cpp` 里的 `kSeedVersion` 加 1 —— 已经烧过旧固件的设备下次开机会自动补写新增的，**已有的不会重复添加**（按内容去重），**你删掉的示例也不会自己长回来**。

`pio test -e native` 会验证每首都解析得通、音符数和拍数对得上。手写转谱最容易漏空格、错符号、算错拍数，这个测试是兜底 —— 4/4 的 8 小节必须正好 32 拍。

# 背单词

翻卡片，`空格` 推进两页：

```
abandon                    abandon     100 words
/əˈbændən/
                           He abandoned
to leave someone           the car in the
or something               snow.
behind
   ① 单词 + 音标 + 释义        ② 例句
```

**为什么例句单独放一页**：字号和信息量直接对冲。实测这 100 条数据，
同屏时只能用 8×16（30 列，释义+例句共 64px）；换成 FreeMono12pt（14×24，
17 列）就要 144px，而屏幕只有 135px。例句拆出去之后每块各自占满，才能上
大字号。第一页的像素预算：单词 32 + 音标 16 + 释义 3×24 = 120，装进 135。

**页内没有按键提示** —— 两页都排满了，没有空白可用，提示写在菜单页
「2 VOCAB」的旁边。

释义和例句用英文（不是中英对照）。这个选择顺带省掉一大块工作：中文要
`efontCN_16`，实测 +312KB 且是**双宽**字体（ASCII 8px、汉字 16px），折行
必须按像素算；纯英文下用等宽字体，按字符折行就是对的。

## 按键

| 键 | 作用 |
|---|---|
| `空格` | 单词+音标+释义 → 例句 → 下一个词 |
| `⏎` | 跳过（不看例句直接换下一个 —— 这个词已经会了） |
| `` ` `` | 回菜单页 |

出词是**纯随机**（每次独立均匀抽取），不洗牌、不记进度、不做间隔重复。
代价要知道：100 个词抽 100 次，大约有 37 个词一次都不会出现。

## 加单词

往 `lib/vocab/wordlist.cpp` 的原始字符串里粘贴，一行一个词：

```
word | phonetic | definition | example
```

| 规则 | 说明 |
|---|---|
| 分隔符 | `\|`，**只取前三个**作分隔，所以例句里可以含 `\|` |
| 音标 | 可空，但只能用白名单里的符号（见下） |
| 释义 | 必填 |
| 例句 | 可省 |
| 空行 / `#` | 忽略 |
| 两侧空格 | 自动去掉，所以可以对齐 `\|` 让词表好看 |

### 音标能用哪些符号

这是**真实的硬约束**，不是风格问题。`efontJA_16` 覆盖英语音标所需的 44/47 个
符号，缺三个：

| 缺失 | 怎么处理 |
|---|---|
| `ɪ` U+026A | **手写字形补上**（`src/ipa_text.cpp`） |
| `ɛ` U+025B | **手写字形补上** |
| `ɝ` U+025D | 不补 —— 词表里一律改写成 `ɜr` |

另外 IPA 的 `ɡ` U+0261 也没有，塞音一律用 ASCII 的 `g`。

efont 的 JA/TW/KR/CN 四个变体我逐个验证过（把字形渲染到离屏画布算位图指纹
——四个变体里这三个符号的指纹完全相同，都是同一个缺字方块）。**JA 覆盖最广，
TW 和 CN 连 `ə` 都没有。**

白名单在 `vocab::kPhoneticWhitelist`，单元测试拿它对账。用了表外的符号会在
设备上显示成方块，而这在 Mac 上完全看不出来。

改完把 `lib/vocab/wordlist.h` 里的 `kExpectedWordCount` 一起改，然后
`pio test -e native` 会把这些规则全对一遍：

| 检查 | 为什么 |
|---|---|
| 释义 / 例句**折行后** ≤ 3 行 | FreeMono12pt 是 17 列。断言行数而不是字符数 —— 两者不等价，字符数够但行数超的词条会被静默截掉一行 |
| 释义 / 例句 ≤ 60 字符 | 写词表时更直观的指标，比折行更严 |
| 音标符号在白名单内 | 见上。这是唯一能挡住「设备上显示成方块」的防线 |
| 音标 ≤ 30 个字形 | 音标是 8px 等宽，屏幕 30 格。按**码位**算而不是字节 —— UTF-8 一个 IPA 符号占 2 字节 |
| 单词、释义、例句纯 ASCII | 手滑打出中文引号 `“”` 或长破折号 `—` 在设备上显示成空白，在 Mac 上完全看不出来 |
| 单词不重复 | 纯随机出词时重复词会莫名其妙多出现 |
| 每条都有音标和例句 | 格式允许省，但内置词表不该偷懒 |

内置的 100 个词是考研 / 雅思托福层。**释义和例句是撰写的，不是词典原文** ——
测试能保证格式和长度，保证不了释义本身的准确性。

# 电视遥控器

以 **BLE HID（HOGP）** 伪装成蓝牙遥控器，电视按标准蓝牙配件配对。

| 键 | 作用 |
|---|---|
| `;` `.` `,` `/` | 上 下 左 右 |
| `⏎` | 确定 |
| `=` `-` | 音量 + / − |
| `m` | 静音 |
| `b` | 返回 |
| `h` | 主页 |
| `p` | 电源 |
| `` ` `` | 回菜单 |

**配对**：电视 设置 → 遥控器与配件 → 添加配件，找 `Cardputer Remote`。Android 侧是
Just Works，不用输 PIN。

> **重新烧固件后需要重新配对** —— NimBLE 的绑定信息存在 NVS 里，重刷固件会失效。
> 先在电视上删掉旧的 `Cardputer Remote` 再重新添加。

## 为什么是 BLE 而不是经典蓝牙

不是选择，是硬件限制：ESP32-S3 只有 BLE（`sdkconfig` 里 `CONFIG_BT_BLE_ENABLED=y`，
**没有** `CONFIG_BT_CLASSIC_ENABLED`）。框架自带的 `BluetoothSerial` 在 S3 上用不了。

所幸 Android TV 的蓝牙遥控器本来就走 HOGP，正好对上。用 `NimBLE-Arduino` 而不是
框架自带的 Bluedroid `BLE` 库 —— 实测边际成本约 216KB flash，Bluedroid 更大。

## 两份 HID 报告

| 报告 | 内容 | 为什么 |
|---|---|---|
| ID 1 Keyboard | 方向键、回车 | Android 的 UI 导航基本只认键盘键码 |
| ID 2 Consumer Control | 音量、静音、电源、主页、返回 | 遥控器专用 usage |

「返回」在 Android 上有时认键盘 ESC、有时认 Consumer 的 AC Back。实机测这台小米电视
走 Consumer，所以 ESC 那条去掉了。

## 一个踩过的坑：notify 的延迟取值竞争

**症状**：配对成功，前几次按键有效，之后按键全无反应，但蓝牙仍然连着。

**根因**：用了无参数的 `NimBLECharacteristic::notify()`。它的 `connHandle` 默认是
`NONE`，会落到 `ble_gatts_chr_updated()` —— 那是异步的，只告诉栈「值变了」，
**栈在真正发送时才去读特征的当前值**。而 HID 一次按键要连发「按下」「松开」两份，
第二份会把值覆盖成松开；栈若还没发出第一份，发送时读到的就是松开，按下那份就丢了。

「前几次有效」是因为栈空闲时发得快、竞争赢；积压之后稳定输。而且那条代码路径
**无条件 `return true`**，连检查返回值都发现不了。

**修复**：改用 `notify(value, length)` 重载 —— 它立刻把数据快照进 mbuf，没有延迟
取值，且返回真实错误码。屏幕上保留 `notify-fail` 计数，真出问题时看得见。

# 代码结构

纯逻辑和硬件严格分开。`lib/` 下的库零硬件依赖，所以能在电脑上跑单元测试，
改语法规则、改词表都不用烧板子：

```
lib/jianpu/        简谱语法解析、音级→频率、播放时间轴
lib/texted/        光标算术、按字符折行（简谱和背单词共用）
lib/songs/         10 首内置曲子（含拍数对账）
lib/vocab/         词表解析 + 100 个内置单词（含音标）
lib/remotemap/     遥控器按键 → 动作 的映射表 + 冲突检测
lib/vizmodel/      全屏可视化的纯逻辑：调色板、频谱柱、卷帘、波形、拍点、播放时钟
src/main.cpp       页面状态机：菜单 ↔ 简谱三页 ↔ 背单词 ↔ 遥控器
src/player.cpp     非阻塞播放器
src/viz_app.cpp    全屏可视化页（四种风格 x 四种配色）
src/library.cpp    LittleFS 曲库
src/vocab_app.cpp  背单词页（两页卡片）
src/ipa_text.cpp   逐码位画音标 + 手写补两个缺失字形
src/remote_app.cpp BLE HID 遥控器页
test/              109 个用例，pio test -e native 约 5 秒跑完
```

三个 app 的状态互不可见：各自的状态全封在自己的 `*_app.cpp` 里，`main.cpp`
只知道「开始 / 画一帧 / 喂按键」这三件事。每加一个 app，之前的页面代码一行没动。

`lib/remotemap` 单独拆出来是有具体理由的：这个项目已经被按键冲突坑过一次（简谱里
`,` `.` `/` 是低音点/附点/减时线，撞了社区惯例的方向键）。测试断言没有两个键指向
同一个动作、没有键重复、映射表和查找函数一致 —— 三种手改映射表时的典型错误都验证过
确实能抓到。

曲库挂在分区表 `default_8MB.csv` 的 `spiffs` 分区（偏移 0x670000、1.5MB）。一首歌一个纯文本文件，**内容就是谱面原文，所见即所存** —— 以后要加 SD 卡导入导出或用电脑写谱，格式天然兼容。一首几百字节，够存几千首。

# 实测得出的约束

写在代码注释里，改动时别踩回去：

- **发声只占时长的 85%**，留 15% 静音间隙。否则连续相同的音（`3 3 3`）会粘成一个长音，听不出是三下。
- **播放器必须非阻塞**。用 `delay()` 的话播放期间整机锁死：按键无响应、不能中途停止。所以 `Player` 是个 `millis()` 驱动的状态机，主循环始终空着能读键盘。
- **`upload_port` 用通配符 `/dev/cu.usbmodem*`**，不能留空靠自动探测：macOS 上 PlatformIO 会挑中 `/dev/cu.Bluetooth-Incoming-Port` 然后卡死。写死具体端口号也不行 —— 换个 USB 口号就变了。
- **背单词页全用灰度**。黄色和青色在这块 1.14" IPS 上太刺眼（实机看出来的）。释义和例句用同一个灰度值 `0xD69A`、同字号 —— 之前用暗灰当「次要信息」会让同样大的字看起来更细更小，被反馈成「字号小了」。
- **手画的字形必须回读验证，不能只靠编译通过**。方法：渲染到离屏画布，逐像素读回来以 ASCII art 从串口打出去。补 `ɪ` `ɛ` 时第一版画在第 5-12 行，正是这样看出来底部衬线比字体的 `l`/`i` 高了一行（x 高度带应该是第 6-13 行，从 efont 自带的 `ə` 量出来的）。
- **BLE 的 HID 报告必须用 `notify(value, length)`，不能用无参的 `notify()`**。后者异步取值，和紧随其后的「松开」报告竞争，症状是「前几次有效之后失效」，而且无条件返回 true 查不出来。详见遥控器章节。
- **判断字形「有没有」要比位图指纹，不能看 `textWidth()`**。缺字的码位同样返回 8px 宽度，只是画出来是个方块。四个 efont 变体的 IPA 覆盖情况就是这么测出来的。
- **词表的屏幕约束要断言折行后的行数，不能只断言字符数**。按单词贪心折行时，60 个字符可能需要 3 行（例如 `20 + 空格 + 20 + 空格 + 15` 会在两个空格处断开），而屏幕只画 2 行，第 3 行被静默丢掉。只查字符数的话这种词条能通过测试却在设备上显示不全。
- **`build_unflags = -std=gnu++11` 不能删**。espressif32 会在我们的 flag 之后追加它自己的 `-std`，gcc 取最后一个，所以只写 `build_flags` 无效。不 unflag 的话设备侧是 C++11，Mac 上测过的代码会在板子上编不过。
- **示波器的相位不能写成 `2π·f·t`**。换音时 `f` 跳变会让相位整体跳一大截，和「换音不跳变起点、只变密度」自相矛盾。固定角速度（`wavePhase` 只吃 `elapsed`）是唯一能同时满足「连续滚动」和「纯函数、可冻结」的写法。
- **每帧调用的函数不能返回 `std::vector`**。卷帘每秒要算 30 次方块表，在无 PSRAM 的 ESP32-S3 上持续搅动堆。所以 `rollBlocks` 由调用方给固定容量数组、函数只填不分配。容量按「一屏画得下的上限」给（240px 宽、一个方块至少 1px → 240 个）；真装不下时保留以「现在」为中心的那一段，**不能填满前 cap 个就收手** —— 300 BPM 的 0.125 拍音符光竖线左边就有 80 个方块，按顺序填 64 个槽会把正在响的音整个挤掉、右半屏一片空白。
- **`Player::start()` 和 `stop()` 必须无条件清 `_paused`**。漏了的话「暂停 → `` ` `` 停止 → 立刻播另一首」会带着残留的 `_paused` 进新播放，`update()` 一进来就 return：喇叭全哑、画面冻在第一帧，而 `isPlaying()` 还是 true，看起来像死机。
- **`resume()` 必须按冻结的 elapsed 重新定位音符，不能沿用 `update()` 留下的 `_index`**。`pause()` 记下的 elapsed 比上一次 `update()` 更晚，可能已经跨进下一个音，而 `_index` 还停在旧音上；拿旧下标算补音时长必然得 0（旧音的 hold 早过完了），当前这个音于是要空等一整帧，再由 `update()` 用整段 `holdMs` 重新触发、收尾偏晚。`vizmodel::resumePointAt` 把「一个 elapsed → (下标, 剩余时长)」收成一个函数，`update()` 和 `resume()` 都只经它。
- **「已经没有音要放了」必须当场 `stop()`，不能只 `return` 等下一轮 `update()`**。`resume()` 也会碰到这个点：在最后一个音的尾巴上按 `SPC` 暂停时，`pause()` 记下的 elapsed 可能已经越过 `totalMs`，恢复时就无音可补。早先那版只是 `return`，于是这一轮循环带着「`_playing` 为真、elapsed 已过 `totalMs`」的过渡态走完 —— 可视化页拿 `index = -1` 画一帧空画面，`main` 的「放完自动回曲库页」判断（`!isPlaying() && !isPaused()`）也要空等一轮才成立。判据收在 `vizmodel::shouldStopAt` 里由 `update()` 和 `resume()` 共用，顺带给 `update()` 补上 `_score.notes[index]` 的边界检查（那里原本一道都没有）。
- **画折线的起点要取 `x=0` 的真实采样值，不能拿中线凑**。示波器早先用 `prevY = midY` 起头、循环从 `x=0` 开始，于是第一段总是从固定中线连到首个采样点，相位滚到 `sin≈±1` 时屏幕左缘会立着一根约 53px 的竖线。`vizmodel::waveY` 把这条公式提成纯函数，就是为了让 `x=0` 那一列也走同一条公式并且能被单测钉住。
- **可视化只用一定拿得到的 `bpm` 做拍点，不做小节线 / 小节内拍号**。`jianpu::Header` 只存 `keyRoot` 和 `bpm`，头部行里的拍号在解析时被显式丢弃，「每小节几拍」没有数据来源；而且不能简单拿分子当拍数（本项目的「拍」是 `60000/bpm` 毫秒的四分音符，6/8 一小节是 3 拍不是 6 拍）。
